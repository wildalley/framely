# 原生版开发与构建

Framely · 取景使用 Go + MyGo 实现托盘截图与贴图工具，命令为 `framely`。启动时只显示托盘；每张图片独立开窗，关闭就销毁图片、标注和撤销记录。没有主页、截图历史或工程保存流程。当前版本为 `0.4.1`，使用 MyGo `0.8.3`，发行包功能以实际发布说明为准。

## 使用

从托盘选择「截图」「粘贴图片」或「打开图片」。已有图片继续保留，新图片在另一个窗口打开，可以同时置顶多张图片。截图期间暂时隐藏 Framely 的窗口，结束后恢复仍然打开的窗口。

图片窗口分三块：顶部细栏放撤销/重做、新截图、长截图、录屏、取字、钉住、保存、设置和复制；左侧竖栏放九种标注工具，底部固定「样式」；中间是画布。窗口最小 480 × 360，小图居中显示。顶部栏放不下时，MyGo 工具栏把靠后的操作收进「More」菜单，复制和关闭始终可见；左侧工具栏是一个 Tab 停靠点，上下方向键切换工具，窗口较矮时可滚动。画布右键使用原生菜单。

点「钉住」后只留图片和一圈细橙色描边，置于其他窗口之上，图片在屏幕上的位置保持不变：拖动移动，滚轮或触控板捏合缩放；鼠标停在图片上时底部出现编辑、复制、缩放比例（点击回到 100%）和关闭；双击或点「编辑」回到编辑窗口。宽度小于 132 像素的钉图不显示悬停栏，右键菜单提供同样操作。钉住时标注工具快捷键不生效。

控件跟随系统明暗主题，标注支持移动、缩放、样式、图层以及文字原位编辑。

- `Ctrl/Cmd+C` 复制图片，`Ctrl/Cmd+S` 保存 PNG、JPEG 或 WebP；保存菜单可切换格式，并设置 JPEG / WebP 质量（60%、80%、92%、100%）。
- `Ctrl/Cmd+V` 粘贴到新的图片窗口，`Ctrl/Cmd+W` 直接关闭并销毁当前图片。
- `Esc` 依次关闭样式、取消选中并返回选择工具、关闭图片。关闭不询问未保存修改。
- 从托盘打开「快捷键与设置」或「查看按键」，不需要先截图。工具窗口关闭后也会销毁。
- 设置「复制后关闭图片」适合截完即贴；置顶图片继续保留。沿用既有 JSON 字段 `hideAfterCopy`，不会保留隐藏图片。
- 开机自启由系统管理，登录后在托盘待命；没有托盘时显示设置窗口，关闭最后一个窗口会退出，避免留下无法操作的后台实例。

支持导入和保存 PNG / JPEG / WebP。PNG 和 WebP 保留透明度，JPEG 在白色背景上合成；WebP 使用有损压缩，100% 质量也不表示无损。应用没有工程文件格式，也不注册图片文件关联。

Linux 首次截图使用系统选区；可从设置中点击「允许直接选区」授权。已获静默截图权限时使用 Framely 自己的选区（见下文「选区」）。权限或自有选区不可用时使用系统选区，取消不会创建空窗口。退出会取消正在等待的截图和选区。

Windows 普通截图直接读取桌面像素并使用 Framely 自有全屏选区（见下文「选区」）。不调用系统截图工具、不修改剪贴板、不自动保存图片；仅点保存或按 `Ctrl+S` 后导出。选区直接传递像素，省去 PNG 编码/解码往返，按各屏缩放换算坐标，支持主屏左侧、上方的显示器。这些改进包含在 v0.2.2 中。

### 选区

拖动框出区域，松开后选区保持可调：拖动内部移动，拖动 8 个控制点改大小，方向键微调 1 像素（Shift 为 10 像素），按住空格拖动可在框选时整体移动。选区下方的操作栏选择要做什么，不用重新框选：矩形、箭头、画笔、文字、马赛克（打开编辑窗口并选好该工具）、长截图、录屏、取字、钉住（原位钉在屏幕上，也可双击选区）、保存、打开编辑窗口、取消，以及「复制」（Enter，直接复制到剪贴板，不开窗口）。未框选时 Enter 选中整屏；R 恢复上次在该显示器确认的区域；右键清除当前选区，再次右键或 Esc 取消。鼠标旁的放大镜显示指针下 15 × 15 像素、坐标和颜色值，按 C 复制颜色（#RRGGBB）并退出。框选取字和长截图、录屏自己的框选仍为松开即确认。

托盘按「开始任务 / 文字与颜色 / 图片 / 应用」分组：截图、重复上次区域、长截图、录屏、录屏设置；框选取字、取色器；粘贴图片、打开图片、视频转 GIF、关闭所有贴图；设置与快捷键、退出。「重复上次区域」（`--repeat`）重新截取桌面并直接打开上次确认的区域，本次运行尚未框选过或该显示器已断开时不可用。「取色器」（`--color`）只显示放大镜，点击、C 或 Enter 复制颜色值并退出，右键或 Esc 取消。两者需要 Framely 自有选区：Windows 直接可用，Linux 需先在「权限与长截图」允许直接截图，macOS 暂不支持。

全局截图推荐 `Super+Shift+S`，长截图推荐 `Super+Shift+L`，录屏推荐 `Super+Shift+R`（新字段默认不绑定）。Windows 显示 `Win`、Linux 显示 `Super`，macOS 显示 `⌘`（macOS 暂不支持长截图）；设置页使用独立键帽，悬停可查看完整按键名称。长截图快捷键按一次开始、再次按下完成；原有截图快捷键仍可完成正在进行的长截图。

Wayland 下，截图、长截图和录屏在同一个 GlobalShortcuts 门户会话中注册，设置和托盘显示系统实际分配的按键。点击「配置系统快捷键」打开桌面的配置界面，分别修改三个动作；此处由系统保存，修改结果会自动同步显示，无需再点「保存设置」。应用提供的推荐组合只是首次授权的建议，不能覆盖桌面已保存的绑定；普通设置保存也不会重新注册快捷键。门户版本不足时会提示在系统键盘设置中修改。系统取消授权、拒绝请求和后端不可用不会被当成注册成功。

Windows、X11 和 niri 的快捷键框支持录制、直接填写（例如 `Super+Shift+S`）与推荐值按钮，然后点击「保存设置」。Super 即 Win 键，macOS 上对应 Cmd。长截图、录屏留空表示不绑定；三个动作不能使用同一组合键。录制实时显示修饰键，Esc、取消按钮、切换页签或窗口失焦会取消录制并保留原值。无效组合会在输入框附近提示，系统已占用的按键可能无法录制。

首次注册失败会在设置显示重试入口（`--hidden` 不主动弹窗），授权期间禁止重复提交。原生注册会在候选绑定与配置保存都成功后替换旧绑定；失败时保留原有快捷键。已有配置不会因新增长截图字段而自动改写。

### niri 快捷键配置

niri 的系统门户支持仍在[上游开发](https://github.com/niri-wm/niri/pull/4744)。当前门户注册失败时，普通启动会弹出「配置 niri 截图快捷键」确认框；也可以在设置里点「配置 niri 快捷键」。这是应用修改桌面配置前的确认，框中列出组合键、执行命令和文件。确认前不修改配置；`--hidden` 启动不会主动弹出。

确认后，Framely 先备份原配置，用 `niri validate` 检查完整候选，再在 niri 配置末尾引用同目录中由本应用管理的按键文件。按键文件以 `--capture` 等参数执行当前安装的程序，支持应用未启动时直接截图。已有同组合的桌面操作会由截图替换；换成其他按键时，旧组合原来的操作自动恢复。配置和设置保存失败会回滚；确认期间文件被其他程序修改时停止操作，要求重新确认。

支持默认配置路径、`NIRI_CONFIG` 与运行中 niri 的绝对 `--config` 路径，以及普通/原始字符串 include、注释、禁用节点与 Super/Alt 的 Mod 别名。配置路径为符号链接、使用无法识别的复杂语法或循环引用时，会停止自动修改并提示手工处理。

确认配置后，托盘、设置和帮助会显示按键及「niri」。绑定由桌面持久管理，退出应用后仍可用于再次启动截图。若要移除集成，删除 niri 主配置末尾由本应用添加的 include 及其按键文件即可恢复原操作；文件和备份的完整路径列在配置确认对话框中，备份保存在 niri 配置目录。

Windows/macOS 交互、真实 Wayland 授权与多显示器选区仍需桌面验收；跨平台构建和独立 D-Bus 协议测试不能代替这些检查。

## 长截图与文字识别

从图片工具栏的「长截图」按钮、托盘「长截图…」或 `framely --scroll` 进入，自动打开框选，无需先点开始。图片窗口还支持 `Ctrl/Cmd+Shift+L` 打开长截图，`Ctrl/Cmd+Shift+S` 新截图。Windows 在进入前鼠标所在显示器上全屏框选；Linux 已获直接截图权限时先在各屏显示选区，按实际框选所在显示器连接共享来源，无需依赖 Wayland 可能返回的旧鼠标坐标。首次使用该显示器时需在系统提示中选择对应来源；已有授权时直接恢复。缺少直接截图权限时先完成共享授权，门户提供完整显示器坐标时全屏框选，单显示器的 monitor 来源也可直接框选；窗口来源或无法定位的多显示器来源使用图片框选页。用户在系统提示中明确改选其他屏幕或窗口时，以新来源重新框选。框选至少 80 × 160 像素，松开立即开始，无需另点确认。手动模式可连续滚动页面或拖动滚动条，滚动过程中即尝试追加，临时匹配失败会提示并继续采集，滚回重叠内容后可恢复，无需另点继续。选区尽量避开固定浮层、滚动条和动画；保留足够的相邻画面重叠。点「完成」或再次按全局截图快捷键打开图片编辑器，完成时会接收最后一幅画面。

Linux 默认手动滚动，进入时只请求屏幕共享，避免先申请鼠标控制后再次选择来源。支持来源恢复的门户按显示器逻辑位置和尺寸分别记住授权，后续轮换使用门户返回的一次性令牌，不借用另一块屏幕的授权。旧版未区分显示器的授权会检查实际屏幕，迁移到对应屏幕后再选择目标来源；授权被撤销、窗口关闭或显示器布局变化时由系统重新询问。可在「权限与长截图」点击「更换共享来源」清除记忆并重新选择；需要自动滚动时勾选「长截图自动向下滚动」并保存设置。Windows 默认自动滚动。

新截图由自有选区生成时记录原显示器与选区；在图片工具栏点「长截图」或按 `Ctrl/Cmd+Shift+L` 会直接沿用原区域，关闭被转换的截图草稿，不重复框选。太小的截图、已断开的显示器、系统选区未提供坐标、打开或粘贴的图片及已拼接长图使用新的桌面选区。也可直接从托盘「长截图…」或 `framely --scroll` 开始，无需先截一张普通图片。框选或共享授权按 Esc/取消时销毁控制窗口并释放采集状态，下次截图不会重新显示被取消的控制窗口；真实错误保留诊断与重试入口。

Linux 显示器控件默认使用紧凑单行条，优先贴在选区右下角外侧；下方无空间时依次尝试侧面和上方，始终留出 32px 间距。XWayland 小窗口在显示前设置 override-redirect，固定原始坐标，避免 GNOME 重新放置；不会创建全屏透明输入层。紧凑条保留高度、暂停/继续、撤回、完成和取消，匹配异常时显示放慢滚动提示，悬停可查看详细说明。

Windows 10 2004+ 在允许排除采集窗口时显示浮动控制条，可暂停、切换自动/手动、撤回、继续、完成或取消，控制条和选区浮层不会进入采集画面。Linux 对已定位的显示器来源使用位于选区外的小型置顶控件窗口，页面直接接收滚轮、点击和拖动。GNOME 等桌面下仅该控件窗口通过 XWayland 定位，使用软件绘制以避免跨显示连接混用 GPU 上下文；采集与来源授权仍通过 Wayland 门户。niri 的 xwayland-satellite 不缩放 X11 窗口、也不接受程序指定的位置，因此在 niri 上控件改用原生 Wayland 窗口，由 niri IPC（`niri msg action toggle-window-floating` / `move-floating-window`）设为浮动并移到选区旁，随后把焦点交还原窗口。窗口来源使用独立浮动控制条。选区占满显示器、周围没有按钮空间、来源无法定位或 XWayland 不可用时，可按全局截图键完成，仍保留托盘控制。更早的 Windows 或窗口排除不可用时同样使用托盘控制。关闭控制窗口取消此次长截图，控件具有键盘操作和深浅色主题支持。

选中标注或选择绘图工具时，左侧工具栏旁展开样式面板：色点、细/中/粗三档粗细（文字为小/中/大字号）、矩形的直角/小圆角/大圆角，以及不透明度滑杆，每次点击是一步撤销。所选标注在面板下方时，面板移到画布右侧。绘制过程中自动隐藏；再点一次当前工具或按 Esc 收起。精确数值、截图圆角、图层和删除在「更多…」或左下角「样式」面板。设置与全部按键说明合并在「设置与快捷键」，也可从图片窗口按 `Ctrl/Cmd+,`；开机自启位于「常规」页签，截图授权和屏幕共享说明位于「权限与长截图」。这些图片窗口快捷键在输入标注文字时不会触发。

形状标注画完即选中并进入调整模式，可直接拖动标注或八个控制点；再次选择工具可继续绘制。画笔、荧光笔保持连续绘制。OCR 的确认框选页可框内拖动、拖动边缘缩放，并支持方向键移动和 Shift+方向键调整右边/下边；长截图以松开立即开始为默认交互。

矩形圆角和截图圆角可从第二行属性栏调整；「样式」弹层继续提供完整预设、连续调节、文字编辑和图层操作。两者分别提供 0–100% 圆角比例及预设，百分比表示短边一半的比例，100% 为胶囊形/最大圆角。预览、复制、OCR 和导出使用相同裁切；PNG/WebP 保留透明，JPEG 的四角为白底。圆角设置按图片独立保存于当前编辑历史，支持撤销和重做，关闭图片后释放。

Windows 采集组件使用 Windows Graphics Capture，要求 Windows 10 1903 或更新版本；自动模式在选区中心发送滚轮。目标窗口改变、鼠标移开或输入被拒时暂停。普通权限无法向管理员权限程序发送输入时，改用手动模式；应用不会自行提权。

Linux 通过系统 ScreenCast 选择器授权屏幕共享，用 PipeWire 持续采集；自动模式要求 RemoteDesktop 同时提供并授予指针控制。GNOME/KDE 是否可用以实际门户能力及授权结果为准，不能仅凭桌面名称判断。当前 niri 没有提供该指针接口，因此使用手动模式。屏幕共享与快捷键授权是独立的，授权取消会释放候选会话。截图过程中不要切换采集源的尺寸；滚动超过重叠范围、重复图案、反向或动态内容导致无法可靠匹配时暂停并保留结果。

如果 niri 点击开始后不出现来源选择器，检查用户门户配置：niri 需要 `xdg-desktop-portal-gnome` 提供屏幕共享；使用 Hyprland 后端可能使 `hyprland-share-picker` 崩溃。在 `~/.config/xdg-desktop-portal/niri-portals.conf` 的 `[preferred]` 中配置 `org.freedesktop.impl.portal.ScreenCast=gnome`，保留自己所需的其他后端设置；备份后再修改，重新登录或重启桌面门户生效。应用会诊断这一冲突，并提供重新检查入口。等待系统窗口期间可以取消，不必退出进程。

Linux 组件支持普通 CPU 缓冲区和线性 DMA-BUF；DMA-BUF 按实际步长、偏移及 fd 存储范围映射并同步，不能把其 `maxsize=1` 哨兵值解释为实际图像长度。非线性 GPU 布局不会直接当作线性像素读取。

CPU 格式与 DMA-BUF 分别协商，DMA modifier 为必需属性；只有实际协商出 modifier 时才请求 DMA-BUF。修复此前 GNOME 将普通内存来源混入 DMA 协商、产生空缓冲区并持续超时的问题。本机已通过 2560×1440 GNOME 实际首帧检查，SPA 协商回归覆盖 CPU 来源拒绝 DMA 格式并正确回退。

拼接最多保留 2400 万像素、高 30000 像素；达到限制后可完成当前图片。预览使用缩略图，完成时才生成整张像素，保存仍用完整分辨率。macOS 暂未实现长截图采集组件，发行包包含离线 OCR。

图片窗口工具栏「识别文字」一击识别整图，识别中可点击取消；右键菜单提供框选识别；`Ctrl/Cmd+Shift+O` 识别整图。托盘「框选取字…」或 `framely --ocr` 会直接打开取字结果，省去图片编辑器这一步；可在桌面快捷键设置中绑定该命令。识别处理当前标注后的画面，马赛克不读取底下原图。先选区域，获得全局识别名额后才合成选区，避免多个窗口排队时各自生成整张合成图。

结果默认显示类似「大爆炸」的词块：中文本地分词，英文、数字、邮箱、网址尽量保持完整；点选、拖动连续选择/取消或 Shift 连选，再按原文顺序组合复制。支持全选、反选、清空和单字模式；方向键在一组词块中移动焦点，空格切换，`Ctrl/Cmd+A` 全选，`Ctrl/Cmd+C` 复制已选内容。「全文编辑」可纠正识别结果，切回选词时重新分词并清空选择。长图每完成一个区块就更新结果，取消后保留已完成文字。

取字窗口的「翻译」页把识别出的全文发给设置中选择的翻译服务（DeepL、百度翻译、腾讯翻译君或兼容 OpenAI 的 `/chat/completions` 接口），原文与译文左右对照，可切换「自动 / 译成中文 / 译成英文」并复制译文。「自动」把以中文为主的文字译成英文，其余译成中文。托盘「框选翻译…」、选区操作栏「翻译」和命令行 `--translate` 在识别完成后直接打开这一页。未选择服务时只显示设置入口，不发送任何内容；超过单次请求长度的文字按行分段发送，一次最多 20000 字。密钥通过 MyGo `Secrets` 保存在系统密钥库（macOS 钥匙串、Windows 凭据管理器、Linux Secret Service），配置文件只记录所选服务、方向、接口地址和模型；设置页的「测试翻译」用当前填写的内容试译一句，不保存。Linux 没有 Secret Service（如 GNOME Keyring、KWallet）时无法保存密钥。

「离线模型（本机）」使用 OPUS-MT（赫尔辛基大学，英→中 Apache-2.0、中→英 CC BY 4.0）的 8 位 ONNX 导出，由文字识别组件以 `--translate` 单次运行：加载模型、逐行贪心解码、输出后退出，不常驻内存，单次约 1 秒。模型发布在 GitHub Release `translate-models-v1`，每个方向约 110 MB，只在设置中点「下载」时获取；应用内固定每个文件的大小和 SHA-256，边下载边校验，写入 `.part` 后才移入，取消或校验失败不会留下看似已安装的文件。模型保存在 Linux 的 `~/.local/share/Framely/models`（或 `$XDG_DATA_HOME/Framely/models`），其他系统在应用数据目录的 `models` 下，可在设置中删除。离线译文质量低于在线服务，中译英通常可用，英译中可能丢失部分含义。旧版文字识别组件不支持离线翻译时会提示重新安装。

关闭来源图片、关闭识别窗口或点击取消会终止当前 OCR。识别超时为 3 分钟（包含排队），输入最多 3200 万像素，输出最多 20000 行、2 MiB 文字。全局仅一个模型进程，连续识别复用模型，空闲 45 秒、取消、错误或程序退出时回收进程。UI 仅保留文字，分词词典按需加载。

完整 Windows/Linux/macOS 包附带 RapidOCR 3.9.2、PP-OCRv6-small ONNX CPU 模型和独立运行时，不需要安装 Python，不上传截图、不在运行时下载模型。长图分块识别，仅对跨块且有文本重叠的片段去重合并，同行独立表格单元格保持分开；复杂多栏排版和表格暂不重建文档结构。当前实现和实测见 [OCR 流程说明](OCR_WORKFLOW.md)。

## 区域录屏

截图后可直接点击图片工具栏「录屏」并沿用该区域。托盘「录屏设置…」打开录屏窗口，选择 30/60 fps 和最大分辨率后直接框选，成功开始后记住区域和参数，可通过「录制上次区域」或录屏快捷键再次录制，无需重选；显示器或来源变化时回到选区。「重新选区…」可更改范围。视频自动保存到「视频/Framely」（可在设置「录屏」页修改或改为每次询问）。录制中主窗口隐藏，录制区域外侧显示浮动控制条（计时、暂停/继续、结束），托盘显示录制状态与计时；独立录屏快捷键或再次执行 `framely --record` 会结束保存。录完可在「转 GIF」页导出，也可从托盘「视频转 GIF…」处理任意 MP4。关闭录屏窗口、正常退出应用会先结束保存。当前版本录制无声视频，完整流程、GIF 导出和平台验收范围见 [录屏说明](RECORDING.md)。

## 开发与检查

需要 Go 1.27.3 或更新版本。Linux 原生窗口需要 GTK3、DBus、AppIndicator 和 `xdg-desktop-portal`，不需要 WebKitGTK。Wayland 需要适合桌面环境的 portal 后端。

```bash
# 在仓库根目录运行；开发组件目录必须显式指定为绝对路径。
export SCREENPIN_COMPONENTS_DIR="$PWD/resources/$(go env GOOS)-$(go env GOARCH)/workers"
go run ./cmd/framely
go run ./cmd/framely --capture
go run ./cmd/framely --ocr
go run ./cmd/framely ./example.png
go test -race ./...
go test -tags nodynamic ./internal/render
go vet ./...
bash scripts/test-capture.sh # Linux 原生缓冲区协议及 DMA-BUF 哨兵/步长/边界回归
```

在真实 Linux 桌面手动检查来源选择器及首帧时，可运行 `SCREENPIN_LIVE_CAPTURE=1 go test -count=1 -run TestLiveDesktopStream -v ./internal/capture`。该命令会请求真正的系统共享选择；测试不替用户授权，30 秒后取消。自动化协议测试仍使用独立总线，不会请求真实桌面。

默认启动和再次启动都只让托盘待命；`--hidden` 保留为兼容参数。`--capture`、`--scroll`、`--ocr` 和图片参数交给已有实例；三个动作参数互斥，不能与图片参数同时使用。

Linux 门户测试使用独立会话总线，不调用当前桌面的门户。MyGo 无窗口控件回归覆盖文字输入焦点、工具栏溢出与方向键、画布菜单、关闭时的状态释放及异步结果隔离。CI 执行这些检查并构建 Linux、Windows 和 macOS 原生产物。

WebP 编码使用 `github.com/gen2brain/webp`，无需 CGo；系统 libwebp 不可用时使用随程序编译的 Go 后端。`nodynamic` 检查强制使用该后端，以独立解码器核验文件头、尺寸、透明度、裁剪行布局、质量设置和马赛克结果。

## 构建

仅排查 GitHub runner 的 Linux 依赖安装时，可运行 `gh workflow run build-native.yml --ref <分支> -f linux_deps_only=true`。该模式只检查 Ubuntu 软件源和依赖，跳过应用、OCR/媒体组件及安装包构建。

先在目标 Windows/Linux/macOS 上构建组件（不能用 Linux 产物充当 Windows 组件）。构建机需要 `uv`；脚本创建隔离的 Python 3.12 环境并下载依赖，最终使用者无需 Python。Linux 需要 C 编译器、pkg-config、PipeWire 开发头文件；Windows 需要 Visual Studio 的 x64 Native Tools 环境和含 C++/WinRT 的 Windows SDK。

```bash
python scripts/build-components.py
SCREENPIN_OCR_INTEGRATION=1 go test -v ./internal/ocr # Linux；Windows 先设置同名环境变量
```

生成组件位于 `resources/<goos>-<goarch>/workers/`，MyGo 构建会复制到应用旁；发布时保留整个目录，包含模型、运行库和 licenses。构建脚本默认包含离线 OCR，解压后的组件约 350 MiB，实际大小依平台变化。只交叉编译 Go 主程序无法生成完整组件包。CI 在 Windows/Linux 本机编译并上传含组件的产物，另保留三平台 Go 构建检查；CI 配置的增加不等同于本地执行过 Windows 测试。

OCR 和长截图采集组件均需要 protocol 2。OCR 使用有长度边界的 RGB 请求和逐块 JSON 响应；采集收到选区后只传该区域的像素，保留原始坐标与来源尺寸。更新主程序时必须重新构建配套组件；旧组件会提示版本不匹配。打包检查会核对采集组件的 `--protocol-version`，无需授权桌面即可检查版本。

组件只从应用旁的 workers、macOS Resources 或用户安装目录查找，不再扫描当前工作目录及祖先目录。开发时设置 `SCREENPIN_COMPONENTS_DIR` 为 `resources/<goos>-<goarch>/workers` 的绝对路径；该覆盖是唯一查找目录，缺失时直接报错，不会混用旧安装组件。OCR 集成测试在没有显式覆盖时会使用测试仓库的构建目录。

OCR 构建使用 `uv pip sync --require-hashes --only-binary :all:` 和两个跨平台锁文件，包含 Windows/macOS 专用依赖，清除旧环境的多余包。修改版本后用锁文件头部的命令重新生成，提交来源文件和锁文件；RapidOCR 单独锁定，完整依赖中用 headless OpenCV 替代其 GUI 包。包内包含 Python 分发依赖的 `sbom.cdx.json`，manifest 记录源码和锁文件哈希；这份清单不覆盖所有系统库、模型和 Go 主程序。Actions 已固定到完整提交 SHA，并提供每周 Go/Python 漏洞扫描与 Dependabot 更新配置。

普通图片、截图解码与 OCR 统一限制为 32 MP、最长边 32768；采集屏幕仍保留 16384 边长限制，长图拼接保留更低的 24 MP / 30000px 限制。文件和门户读取上限为 220 MiB，先检查图片头再解码。多窗口图片共用 512 MiB 的估算预算（每像素 13 字节加固定开销），加载失败、窗口关闭与后台任务结束会释放。长截图开始滚动前按最大拼接尺寸预留结果额度，完成后按实际尺寸缩减；预算不足会在开始前提示，取消会归还预留。它不是整个进程的 RSS/GPU 硬上限，采集流、编码数据、历史和 OCR 子进程另有生命周期。每个窗口的撤销/重做历史最多 80 步、保守估算 32 MiB，当前文档内容不会因历史裁剪被删除。

```bash
go tool mygo build -platform linux/amd64,windows/amd64,darwin/arm64 \
  -skip-installer -skip-dmg -skip-notarize
```

产物位于 `build/native/<platform>/`。开发机也可用 `go build -o build/native/framely ./cmd/framely` 快速编译；安装时使用 MyGo 构建，保留应用标识和系统集成元数据。

Linux 本地测试先执行 `python scripts/build-components.py`（可重复运行）重建全部组件，再用 `go tool mygo build` 打包，最后执行 `python scripts/install-local-linux.py [--image 图片]` 安装主程序和完整组件到当前用户的 `~/.local`，备份旧版本并重启。只重新打包而沿用旧组件会导致协议不匹配，程序会提示重新安装配套组件。该操作会退出已有实例，请先完成正在编辑的图片。

Linux 安装入口使用固定的门户应用 ID 命名（见 `internal/capture` 的 `AppID`），截图、屏幕共享和快捷键授权都绑定这个 ID，升级后授权保留；SDK 默认按应用代号命名入口，下述 Arch 配方同样使用固定 ID。`scripts/package-release.py` 会修正 SDK 生成的 deb 和便携安装入口，并校验组件与真实 OCR。

## Arch 原生包

在 Arch Linux 仓库根目录执行：

```bash
cd packaging/arch-native
makepkg --syncdeps --cleanbuild
sudo pacman -U ./framely-0.4.1-1-x86_64.pkg.tar.zst
```

该配方从当前工作区构建，支持 x86_64 和 aarch64，并排除本地凭据、代理状态和编译产物。Arch 包名为 `framely`，提供 `framely` 命令，并替换旧版包；已有设置保留。安装前请从托盘退出旧实例。

## Release 构建

推送 `v*` 标签运行 `.github/workflows/release-native.yml`，先完成同一提交的全部测试和 Windows、Linux、macOS 两种架构的本机构建，以及 Arch 包构建。所有包内的 OCR 都会在打包后验证。七个附件齐全、版本一致且校验成功后才创建公开 Release；任一构建失败不会发布不完整的版本。

Mac 发行构建使用 macOS 15 运行器，分别生成 arm64/amd64 DMG，执行 ad-hoc 签名并检查签名；未配置开发者证书与公证。Windows 生成 NSIS 安装程序和完整便携包。Linux 安装包与便携安装使用同一个固定门户应用 ID，升级后授权保留。

目标系统的发行构建先执行 `go tool mygo build -platform <goos>/<goarch> -skip-dmg -skip-notarize`，再执行 `python scripts/package-release.py`。后者会验证版本、组件与真实 OCR，并收集安装包。macOS 还会补齐 MyGo 0.7.4 忽略的 `.dylibs` 目录，重新封装签名，再创建并校验 DMG。Intel macOS 使用仍提供 x86_64 预编译包的 ONNX Runtime 1.23.2，其他平台使用 1.24.4。
