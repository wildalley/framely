# 安全、正确性与性能修复（2026-11-16）

本次修改基于 `main` 的 `8ba27b0`（v0.4.6）。开始审查时已同步远端，确认本地与 `origin/main` 一致、GitHub 最新发布为 v0.4.6。以下修改包含于 v0.4.8。

## 按优先级完成的修复

1. **翻译请求的传输限制。** 设置与请求复用同一地址校验规则：远端服务必须使用 HTTPS，HTTP 仅允许 `localhost` 与回环 IP。所有客户端（包括传入的自定义客户端）都会阻止 HTTPS 降级跳转。保留原来的超时、传输与自定义跳转限制，不修改调用方客户端。旧地址不会被自动替换到另一家服务，也不会导致快捷键重置；启用该服务前需要改为 HTTPS。
2. **离线翻译长行完整性。** 每行按原始 SentencePiece token 分块，每块为目标标记与 EOS 留出空间，优先在附近句末切分，不经过解码再编码。按块长度组批，输出按原行与原块顺序恢复，空行保留。输入超出单块长度不再丢弃尾部；输出达到长度上限但未完成时明确返回错误。
3. **高亮遮罩计算。** 用水平带内的 X 区间合并替代矩形与网格单元的三重遍历。所有未覆盖区间仍在同一路径中绘制，保证重叠区域不会重复变暗。编辑器仅缓存当前矩形与路径；位置、尺寸或高亮集合变化会更新缓存，关闭图片会释放缓存。导出使用独立路径，后台任务不共享编辑器缓存。
4. **下载取消与重试。** 每次下载使用独立临时文件，校验大小和 SHA-256 后移入目标。全局按模型目录协调下载与删除；新窗口的下载会等待旧任务完成清理，排队取消不需要等待旧网络请求结束。没有任务使用时删除协调记录。
5. **分片视频时长。** 普通 MP4 继续读取 `mvhd`；分片 MP4 中时长为零或未知时，使用内置 FFmpeg 读取输入元数据和索引，不转码整段视频。过程限制为 5 秒，日志有界，关闭窗口可取消；缺失或无效时长不作为成功结果。同步收紧 MP4 box 的边界与溢出检查。

## 高亮性能

机器为 Intel Core Ultra 7 265KF，Linux。输入为 4096×4096 画布内分别具有不同 X/Y 边界的矩形，与审查时复现使用同一组坐标。

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 300 个矩形路径生成 | 78.43 ms/次 | 0.169 ms/次 |
| 同一操作临时分配 | 314,056,120 B/次（约 300 MiB） | 539,686 B/次（约 0.51 MiB） |
| 未变化的 300 个矩形缓存查询 | 未提供缓存 | 268.8 ns/次，0 B 分配 |

路径生成耗时约降低 99.8%，临时分配约降低 99.8%。数据衡量几何构造与缓存查询，不等同于整张图片在各平台上的绘制耗时；矩形分布也会影响结果。

## 代码质量复查

已有按领域划分的包、独立逻辑测试、窗口释放回归和竞态检查，可继续维护。主要问题集中在桌面层的配置传播、异步任务归属，以及同一业务在不同入口重复实现；静态检查通过不能替代这些行为检查。

按优先级完成以下改进：

1. **P1，配置与异步状态一致性。** 应用统一向图片和 OCR 窗口发布成功保存的配置。原来的 OCR 窗口捕获创建时的配置，从设置页启用或切换服务后仍使用旧服务。现在更新名称、离线状态、地址、模型及默认方向；服务配置变化会取消旧请求、清空旧译文，并丢弃已排队的迟到结果。无关设置保留译文与窗口里单独选择的方向。保存设置本身不发起翻译，进行中的自动翻译也需用户重新触发。
2. **P1，任务随应用退出取消。** OCR 翻译使用应用上下文；请求结束释放自身上下文，以请求代次识别可以更新窗口的结果。统一 OCR 识别与翻译的主线程投递，移除重复的关闭/退出判断。
3. **P1，翻译入口行为一致。** 设置页测试原来单独组装请求，漏接离线后端，还会读取离线服务不存在的密钥。设置测试与 OCR 翻译现在共用服务配置、密钥合并和离线后端，离线模式不访问系统密钥库。
4. **P2，保留诊断原因。** 视频探测明确处理启动失败、预期的 FFmpeg 输入检查退出码 1、其他进程失败及取消。保留可通过 `errors.Is` / `errors.As` 获取的原因和有界诊断日志；界面继续显示简明提示，完整原因记入应用日志。头部读取与后备探测共享一个超时预算。
5. **P2，并发协调职责独立。** 模型目录的操作协调器成为具名类型，独立管理排队与引用释放，下载逻辑专注网络与文件校验。增加 `RemoveContext`；关闭设置时，排队中的删除任务可以取消。

## 会话层分离（续）

继续完成前次复查提出的录屏/长截图结构改进：

- **录屏会话。** `internal/recording/session.go` 管理录屏启动、暂停/继续、状态轮询、保存确认与文件发布；原生源通过小接口接入。窗口层分为启动快照、保存位置选择、区域准备、状态展示和统一窗口恢复。后台任务使用启动时快照，不读取会被下一次操作替换的命令通道。
- **中断文件与错误。** 准备失败移除临时文件；已经尝试录屏后，非空片段保留。只有源关闭并确认完成后才发布；发布前取消保留片段。启动命令失败但已写入数据时也返回带路径的 `RecoveryError`，保留可通过 `errors.Is` / `errors.As` 检查的原始原因；空文件不会被宣称可恢复。
- **长截图会话。** `internal/scrollshot/session.go` 管理帧读取、暂停/继续、撤回、自动输入、结束前的稳定帧和采集源断开后的审阅；不依赖桌面工具包。准备来源/选区、安装控制窗口、交接完成图片分别留在桌面适配层。进度回调传递独立像素预览和按值状态，不传递正在变化的控制器。
- **关闭与交接。** 两种会话都处理关闭的命令通道，避免空转或等待不存在的控制器。长截图在源断开时关闭采集并保留审阅；正常完成保持原来的门户时序，图片交接排队后再关闭源。准备阶段与会话共享一次关闭机制。
- **重复逻辑。** 录屏和长截图共用显示器匹配与可取消的动画等待。窗口来源不会套用显示器选区；保留负坐标、多显示器及单显示器缺少位置元数据的处理。录屏控制窗、边框和控制条统一刷新。

本轮自动化覆盖会话及现有控件行为；原生门户授权、不同桌面上的窗口恢复和长时录屏仍需真机检查，交叉编译不作为这些检查的替代。

分片视频探测仍依赖内置 FFmpeg 的文本元数据格式；已用真实媒体组件回归锁定行为，后续更换组件版本时需同时运行该集成检查。

## 用户体验优化

按 P1 → P2 实施此前审查的六项问题：

- **选区操作栏。** 800×600 显示器中，选区从 (380,140) 到 (500,300) 时，原工具栏容器仅有 420 DIP，保存、复制、取消等子按钮已被裁切到零尺寸。现在测量文本按钮并按完整工具栏宽度限制位置；空间不足时次要工具和功能进入「更多」，核心操作常驻。回归检查每个按钮的非零可见尺寸及屏幕边界，覆盖边缘选区、两种比例和窄屏菜单动作。
- **翻译状态。** 运行时显示「取消翻译」；保留上次成功译文、原文与实际输出方向，修改原文后可查看旧结果对应的原文。重试、取消和失败不会误标旧结果，迟到请求仍按代次丢弃。设置入口直达翻译页，初始提示包含无需密钥的离线模型。
- **错误恢复。** 翻译缺少密钥、模型或地址无效时提供设置/模型下载入口，完整错误可展开与复制。配置校验返回字段信息，定位对应设置页并在字段旁标出，修正后清除。录屏恢复错误保留结构化路径，提供打开片段与文件夹操作；播放、打开 GIF 或文件夹失败给出提示，保留可复制的诊断。
- **GIF 选段。** 双端时间轴支持拖动及键盘起止点，秒数输入同步选段，跨度限制为 60 秒。使用内置媒体组件读取指定时间帧，180 ms 去抖、5 秒限时，替换任务、换页、换视频和关闭时取消；迟到回调不得覆盖新预览。预览失败可重试，导出入口在最小窗口中保持可见。
- **OCR 扫选。** 指针靠近上下边缘时逐帧滚动，基于已提交帧的可见词块进行连续命中。处理输入消费后同一帧的重复构建，以及已选预览导致列表高度变化的情况；不生成常驻计时器，释放、换页、替换文字和关闭后停止。原生词块键盘语义保留。
- **钉图键盘操作。** Tab 聚焦图片会显示工具栏，焦点在工具栏内时鼠标离开仍保持显示；小图通过菜单键或 Shift+F10 操作，避免覆盖图片。

同时修复窄翻译页重复创建同名布局节点的问题。通过 MyGo Tester 检查交互、明暗主题和窄窗口渲染；内置 FFmpeg 的指定时间帧与首帧像素不同，并保持已有 GIF 导出回归。自动化控件测试与交叉编译不替代原生门户或目标平台真机验收，未更新已安装应用。

## 发布回归补充

v0.4.7 发布构建中的 Windows 平台检查发现，找不到绝对路径可执行文件时，Go 的扩展名查找返回 `exec.ErrNotFound`，而 Unix 启动阶段返回 `os.ErrNotExist`。原代码保留了原始原因，但回归只接受后一种错误。现按这两种平台语义检查启动失败原因；未调整生产代码或降低其他检查。保留原 tag，并以 v0.4.8 重新构建完整发行包。
